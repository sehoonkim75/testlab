이 도구가 하는 일

판정은 사람이 최종 확인하는 것을 전제로 합니다. 이 도구는 “여기를 다시 보라”는 표시를 달아 줄 뿐, 위배 여부를 확정하지 않습니다. 특히 지역명·군 경력·학교 관련 표현은 맥락에 따라 오탐이 생기므로 표시된 행은 반드시 원문을 직접 읽고 판단하세요.

샘플 파일

아래 두 파일을 먼저 열어 보면 입력 형식과 결과 형태를 한 번에 이해할 수 있습니다. 두 파일 모두 같은 예시 데이터(지원자 3명 × 4문항, 12건)를 씁니다.

두 파일은 이 가이드 안에 들어 있습니다

별도 첨부 없이 이 HTML 파일 하나만 있으면 됩니다. 버튼을 누르면 브라우저의 기본 다운로드 폴더에 엑셀 파일이 저장됩니다. 가이드를 메일이나 메신저로 전달할 때도 이 파일 하나만 보내면 됩니다.

입력양식 샘플에는 검토 대상이 되는 사례를 일부러 섞어 두었습니다. 출신학교 노출, 고향 언급, 두 문항에 같은 답변, 타기관명 사용, 답변 공란, 의미 없는 문자 반복 여섯 가지입니다. 처음 도구를 설치했을 때 이 파일을 그대로 돌려 보면, 기준이 제대로 작동하는지 바로 확인할 수 있습니다.

결과 샘플의 열 너비는 읽기 편하도록 조정해 두었습니다. 실제 출력 파일은 열 너비가 조정되어 있지 않으므로 처음 열면 답변 칸이 좁게 보일 수 있습니다.

단계별 실행 순서

1

노트북 열기

처음 한 번만 하면 되는 준비 단계입니다.

  1. Anaconda(또는 파이썬 + Jupyter)가 설치되어 있는지 확인합니다. 없다면 Anaconda Distribution을 설치하면 Jupyter가 함께 들어옵니다.
  2. 작업할 폴더에 자기소개서_불성실탐지_테스트_.ipynb 와 입력 엑셀 파일을 함께 넣어 둡니다. 같은 폴더에 두면 경로 입력이 쉬워집니다.
  3. Anaconda Prompt(또는 터미널)에서 해당 폴더로 이동한 뒤 jupyter notebook 을 실행하고, 브라우저에서 노트북 파일을 엽니다.
  4. 노트북에는 셀이 세 개 있습니다. 위에서부터 차례로 실행합니다. 셀 실행 단축키는 Shift + Enter.
인터넷 연결이 필요합니다

판정은 OpenAI 서버에 요청을 보내 이루어집니다. 사내망에서 외부 접속이 막혀 있으면 실행되지 않습니다.

① 자기소개서 데이터 시트 (필수)

지원자 한 명이 5문항을 썼다면 5행이 됩니다. 아래 6개 컬럼이 모두, 정확한 이름으로 있어야 합니다.

컬럼명넣는 값

중간에 빈 행이 섞이거나 필터를 걸어 둔 상태로 저장하면 결과가 엉뚱한 행에 붙을 수 있습니다. 컬럼명 앞뒤 공백, 줄바꿈, 병합된 셀도 미리 정리해 주세요.

② 평가기준 시트 (선택, 그러나 권장)

같은 엑셀 파일 안에 별도 시트로 만듭니다. 이 시트를 지정하면 코드에 내장된 기본 기준 대신 기관이 실제로 쓰는 기준과 사례가 판정에 사용됩니다. 지정하지 않으면 내장 기준으로 동작합니다.

컬럼명넣는 값
구분“블라인드” 또는 “불성실” 로 시작하는 값. (예: 블라인드-출신학교, 불성실-공란)
기준판정 기준 문장. 비어 있는 행은 무시됩니다.
잘된예시실제로 걸러내야 할 사례를 적습니다.
탐지기준제외예시비슷해 보여도 위배가 아닌 사례. 오탐을 줄이는 가장 효과적인 칸입니다.
‘잘된예시’ 라는 컬럼 이름에 주의

이 칸의 내용은 모델에게 “위반(탐지) 예시” 로 전달됩니다. 이름만 보고 모범 답안을 적으면 정상 답변을 위배로 잡게 됩니다. 반드시 걸러야 할 표현을 적으세요.

지역명 오탐(단순 근무지역 언급을 출신지역으로 판정)처럼 반복되는 문제는 탐지기준제외예시 에 실제 사례를 몇 개 채워 넣는 것으로 상당 부분 줄어듭니다. 항목별로 무엇을 어떻게 적는지는 평가기준 시트 작성법에 표로 정리해 두었습니다.

키가 없으면 실행 중 첫 질문에서 멈춥니다.

  3. 키는 실행 중에 붙여넣어도 되고, 미리 환경변수 OPENAI_API_KEY 로 등록해 두면 그 질문을 건너뜁니다.
실행 중에 붙여넣은 키는 노트북 파일에 그대로 저장됩니다

Jupyter는 입력한 값까지 출력 영역에 기록합니다. 노트북을 남에게 보내거나 저장소에 올리기 전에 Cell → All Output → Clear 로 출력을 지우세요. 이미 공유한 적이 있다면 해당 키는 폐기하고 새로 발급받는 편이 안전합니다.

작성 원칙 일곱 가지

  1. 한 행에 한 기준. 항목을 합치지 말고 쪼개면 결과의 ‘위배유형’ 칸이 명확해집니다.

  3. 예시는 요약하지 말고 원문 그대로. 모델은 뜻이 아니라 표현 패턴을 봅니다. “고향 언급” 보다 “고향인 전주에서 나고 자라” 가 훨씬 잘 작동합니다.
  4. 제외 예시를 반드시 채운다. 반복되는 오탐은 대부분 이 칸 한 줄로 해결됩니다. 실제로 잘못 잡혔던 문구를 그대로 옮겨 넣으세요.
  5. 예시가 여러 개면 / 로 구분하거나 셀 안에서 Alt + Enter 로 줄을 바꿉니다.
  6. 구분 값은 반드시 ‘블라인드’ 또는 ‘불성실’로 시작. 뒤에 항목명을 붙이는 방식(블라인드-출신지역)을 권합니다.
  7. 기준을 고칠 때마다 --dry-run 으로 5건만 확인한 뒤 전체를 돌립니다.

기준을 바꿨는데 결과가 그대로라면

입력 4 단계에서 시트명을 정확히 넣었는지, 그리고 실행 직후 경고 줄이 없었는지 확인하세요. 경고가 떴다면 기관 기준이 아니라 내장 기본 기준으로 판정된 것입니다. 엑셀을 수정한 뒤 저장하지 않은 채 다시 실행하는 경우도 흔한 원인입니다.

중복 판정은 ‘완전 일치’만 잡습니다

기준 문구에는 유사도 90%라고 되어 있지만, 후처리 단계에서 자동으로 잡아내는 것은 글자가 정확히 일치하는 경우뿐입니다. 조사나 어미만 바꿔 쓴 반복은 모델 판정에 의존하므로, 이 유형을 중점적으로 보려면 결과를 받은 뒤 같은 번호끼리 답변을 나란히 놓고 확인하는 절차를 따로 두는 편이 좋습니다.

모델을 바꾸거나 앞 5건만 시험 실행하고 싶을 때 씁니다. 노트북에서는 셀 실행 전에 아래 두 줄을 코드 셀 맨 위에 넣고 값을 지정하면 됩니다.

보안 주의사항

노트북 파일을 그대로 공유하지 마세요

실행 중 입력한 API 키가 출력 영역에 평문으로 저장됩니다. 공유·백업·저장소 업로드 전에 Cell → All Output → Clear 로 출력을 비우고, 이미 파일이 외부로 나간 적이 있다면 키를 폐기한 뒤 재발급하세요.

자기소개서 원문은 외부 API로 전송됩니다. 기관의 개인정보 처리 방침과 클라우드 이용 규정을 먼저 확인하고, 필요하다면 이름 컬럼을 식별 코드로 바꾼 뒤 실행하세요. 판정에 이름 값 자체가 사용되지는 않습니다.

결과 엑셀에는 위배 근거로 답변 원문 일부가 그대로 담깁니다. 원본 자소서와 같은 수준으로 관리하세요.
